### 2. 存储膨胀问题

AIMAPP Candidate 1 单次运行产生约 50 GB 原生输出，主要原因是每个高层动作都保存完整 `model.pkl` 快照，单个文件可达到数百 MB。

后续正式实验应保留最终模型和必要逐步指标，不再长期保存每一步完整模型快照；rosbag 也需重新规划保留策略。

### 3. 发现并验证非零起点坐标问题

Candidate 2 物理起点为：

```text
(-2.5, -2.5)
```

AIMAPP 认知坐标定义为：

```text
cognitive = world - physical_start
```

因此：

```text
raw /odom   ≈ (-2.5,-2.5)
/agent/odom ≈ (0,0)
```

这一部分本身正确。

问题在于 Nav2 静态地图仍保持原世界坐标原点：

```text
(-30.0,-20.5)
```

而 `/agent/odom` 已经切换到以出生点为原点的认知坐标，因此非零起点时 AIMAPP 认知坐标与 Nav2 map 坐标并不一致。

### 4. Nav2 地图原点平移修复

为保持坐标一致，加入：

```text
map_origin_cognitive = map_origin_world - physical_start
```

Candidate 2：

```text
原始地图原点 = (-30.0,-20.5)
物理起点     = (-2.5,-2.5)
平移后原点   = (-27.5,-18.0)
```

运行验证通过：

```text
Original map origin : (-30.000,-20.500)
Physical start      : (-2.500,-2.500)
Shifted map origin  : (-27.500,-18.000)
```

退出后地图恢复：

```text
MAP RESTORE: PASS
```

因此已经确认：**Gazebo 世界坐标、AIMAPP/SCA 认知坐标和 Nav2 map 坐标可以在非零起点下正确对齐。**

当前修复仍在本地，尚未最终提交；`nonzero_start_smoke.sh` 中还混有一次性诊断 probe，需要明天先清理。

### 5. AIMAPP 拓扑目标与 Nav2 实际终点并不总相同

本次抓到：

```text
AIMAPP 拓扑目标        = (-0.460,-0.460)
Navfn 实际路径终点     = (-0.260,-0.410)
机器人实际 agent pose ≈ (-0.248,-0.263)
```

对应：

```text
AIMAPP目标 → Navfn终点 ≈ 0.206 m
Navfn终点 → 实际位置   ≈ 0.147 m
AIMAPP目标 → 实际位置  ≈ 0.290 m
```

Nav2 配置：

```text
Navfn planner tolerance   = 0.5 m
controller xy_goal_tolerance = 0.2 m
```

两者不是“总共 0.7 m 的统一容差”，而是两层不同语义：

- `0.5 m`：精确目标不可规划时，规划器可在目标附近找替代终点；
- `0.2 m`：机器人进入实际路径终点附近即可判定到达。

### 6. 拓扑节点与实际位置的关系

AIMAPP 的拓扑节点代表一个区域，不要求机器人精确停在节点中心。

例如：

```text
节点中心     = (-0.46,-0.46)
实际位置     ≈ (-0.248,-0.263)
二者距离     ≈ 0.29 m
节点影响半径 = 0.5 m
```

因为 `0.29 < 0.5`，机器人仍可认为属于当前拓扑节点。

真正需要检查的是：

> **机器人实际位置是否仍落在当前认知拓扑节点的有效区域内。**

如果实际已经离开该节点区域，而高层仍认为自己处在旧节点，就可能导致后续拓扑状态与真实运动错位。

### 7. AIMAPP 如何处理里程计漂移

AIMAPP 并不是一直相信里程计，而是：

```text
运动
→ odom 连续更新
→ 到达后拍 panorama
→ 根据视觉观测和生成模型更新状态后验
→ 判断最可能所在拓扑节点
→ 若足够确定，则把认知位置重置到该节点
→ 发布 believed_odom
→ 重新调整 /agent/odom 偏移
```

因此其基本思想可以理解为：

> **里程计负责短时间连续运动；视觉 + 状态推断负责拓扑重定位；高层足够确定时，用拓扑节点反向校正认知里程计。**

这属于离散拓扑层面的重定位，不等同于 SLAM 的连续位姿优化。
