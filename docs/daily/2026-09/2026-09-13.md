## 1. 今日目标

## 2. 今日完成内容

### 问题 1：状态信息增益 epsilon 不一致 —— 已修复

确认 AIMAPP 的状态信息增益计算中存在两类不同的 epsilon：状态筛选与条件观测项使用 `exp(-16)`，最终预测观测熵中的对数使用 `1e-16`。SCA-AIFNav 原实现将最终项也错误使用了 `exp(-16)`。

处理方式：仅修正最终预测观测熵项，保留其余 AIMAPP 规则不变。  
提交：`5f7337e fix: match AIMAPP state information gain epsilon`

### 问题 2：MCTS 随机动作采样器与 AIMAPP 不一致 —— 已修复

AIMAPP 使用 `np.random.multinomial(1, probabilities)` 进行随机动作采样，SCA-AIFNav 原实现使用 `np.random.choice(..., p=...)`。两者概率分布等价，但相同随机种子下生成的随机序列不同，会影响严格复现实验轨迹。

处理方式：改为 AIMAPP 同款 multinomial 采样，并保持确定性 tie-breaking 独立。  
提交：`de7fe28 fix: match AIMAPP action sampling`

### 问题 3：深层方向前瞻在越出原始动作扇区后的行为不同 —— 保留 SCA 行为

AIMAPP 在复用节点后即使节点已越出原始动作允许几何范围，仍可能继续后续深层循环；在“越界且后续无匹配节点”的边界情况下，`next_pose_id=-1` 还可能被 Python 负索引解释为最后一个节点。

SCA-AIFNav 在节点越出原始动作范围后直接 `break`，可避免错误地继续扩展和 `-1` 负索引风险。

结论：不修改，作为有意工程差异保留。

### 问题 4：横向想象连接的重复动作占位时机不同 —— 保留 SCA 行为

AIMAPP 会在候选横向动作通过几何有效性检查之前就记录 `prev_action`，因此一个无效候选可能提前占用该动作槽位，阻止后续同一动作下的有效候选。

SCA-AIFNav 只在横向连接真正通过约束并完成证据更新后，才记录该动作用于重复抑制。

结论：不修改，保留 SCA 行为。

### 问题 5：目标导航模式与运行时生命周期未完整接入 —— 已完成

新增三种显式导航模式：

- `EXPLORE`：状态信息增益开启；期望效用关闭；归纳推断关闭。对应 AIMAPP 正式探索模式。
- `GOAL_DIRECT`：期望效用开启；状态信息增益关闭；归纳推断开启。评价项配置对应 AIMAPP 原始目标模式。
- `GOAL_BALANCED`：期望效用、状态信息增益、归纳推断全部开启。作为 SCA-AIFNav 扩展，用于后续比较与消融。

同时补齐以下运行时生命周期：

1. 目标模式默认偏好权重采用 `10.0`。
2. 当前版本要求目标已存在于模型中，不允许静默创建未知目标。
3. 模式切换不重置已学习的 A、B、belief 和认知地图，只更新偏好与评价项并重新执行 MCTS。
4. 模式切换本身不计为新的导航学习周期，也不会增加 `_cycle_count`。
5. 仅重规划得到的新 decision 将 `executed_action_id` 清零，避免之前已完成动作被重复计数。
6. Node 与 Bridge 的当前 decision 缓存保持同步。
7. 物理动作正在执行时禁止切换模式；已完成动作正在等待下一观测完成学习时同样禁止切换。
8. 目标到达后，当前观测仍正常完成模型更新，但不再启动下一动作。
9. 到达目标后保持原 `GOAL_DIRECT` / `GOAL_BALANCED` 模式和目标偏好，不自动切回 `EXPLORE`，等待新的明确任务指令。
10. `place` 目标接口、运行时模式切换、`GOAL_BALANCED` 和目标到达后的停止生命周期属于 SCA-AIFNav 工程扩展；不能表述为 AIMAPP 原样复现。

提交：`1196177 feat: add AIMAPP-aligned navigation modes`

## 4. 参数信息增益暂缓记录

AIMAPP 虽然实现了基于 pA、pB 的参数信息增益，但其正式探索模式和目标模式均关闭该项，并且源码提示该项与其他评价项联合使用时存在尺度协调问题；MCTS 中还额外对其除以 100 进行尺度压缩。

因此当前阶段先完成状态信息增益、目标效用和归纳推断三项的模式化接入。参数信息增益作为后续独立审计项，在完成 AIMAPP 等价复现后再评估是否加入探索模式及开展消融实验。
