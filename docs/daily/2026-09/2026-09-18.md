## 3. Issue 7：LiDAR 安装角改为 TF

原先 SCA 的 LiDAR 方向处理存在通过配置或假设获得安装偏航角的风险。

现正式采用 ROS TF：

```text
LaserScan.header.frame_id
        ↓
tf2 Buffer
        ↓
base_link <- sensor
        ↓
提取 LiDAR 安装 yaw
        ↓
robot yaw + laser mounting yaw + ray angle
```

之后再进入原有 12 方向扇区聚合。

固定结论：

- 不再维护手工 `laser_yaw_offset`；
- TF 暂不可用时，不猜测传感器安装方向，当前 scan 直接忽略；
- 机器人本体与传感器安装关系交给 ROS TF 基础设施维护。

对应 SCA commit：

```text
7562dd6 feat: resolve laser yaw from tf
```

## 4. Issue 8：Potential Field 近目标预检查

AIMAPP 的 Potential Field 路径在极近目标处存在进入归一化计算后出现除零风险的可能。

SCA 当前实现会先检查是否已经处于目标附近，再决定是否继续计算势场。

本轮结论：

```text
保留 SCA 近目标预检查
不为了逐行复现 AIMAPP 而删除安全保护
```

该差异属于有明确工程价值的安全偏差。

同时正式 SCA 主线已经转向 Nav2，因此 Potential Field 仅保留为 legacy/reference backend。

## 5. Issue 9：Nav2 正式成为主运动执行后端

### 5.1 最终架构

正式运行链路固定为：

```text
SCA 主动推断 / MCTS / 认知地图
        ↓
生成认知局部目标
        ↓
认知坐标 -> 物理 odom 坐标
        ↓
Nav2 NavigateToPose
        ↓
LiDAR 更新 rolling costmap
        ↓
NavFn 生成路径
        ↓
DWB 生成实时速度
        ↓
velocity_smoother
        ↓
/cmd_vel
        ↓
Gazebo / 实际机器人
```

职责边界：

```text
SCA   ：决定“去哪”
Nav2  ：决定“怎么过去”
底盘  ：负责“真正动起来”
```

Nav2 不是替代 SCA 的导航算法，而是 SCA 下层的标准运动执行基础设施。

### 5.2 认知坐标与物理 odom 解耦

SCA 内部认知坐标可能因 posterior correction / realign 发生平移修正。

ROS 物理 `odom` 坐标不能随认知校正一起跳变。

因此新增 `OdometryAdapter.physical_position()`，执行认知坐标到原始物理 odom 坐标的逆变换：

```text
cognitive
-> remove alignment offset
-> restore startup odom origin
-> raw physical odom target
```

Nav2 只接收物理 `odom` 目标。

### 5.3 Nav2MotionExecutor

正式行为：

- NavigateToPose goal frame 固定为 `odom`；
- directional action 必须传入对应的 physical target；
- SCA 内部仍保留 cognitive target；
- feedback / goal distance 优先使用 physical target；
- 移除旧 `/initialpose` 发布；
- 不再向 Nav2 传递经过认知对齐后的伪 odometry；
- goal quaternion 使用合法单位姿态：`orientation.w = 1.0`。

### 5.4 Nav2 配置

新增：

```text
sca_aifnav_sim/config/nav2_odom_params.yaml
```

正式配置为 odom-only navigation：

- `global_frame: odom`
- `robot_base_frame: base_link`
- local costmap：rolling window
- global costmap：rolling window
- LiDAR obstacle layer + inflation layer
- NavFn global planner
- DWB local planner/controller
- velocity smoother

正式主线不使用：

```text
AMCL
map_server
static map
/initialpose
```

### 5.5 TF 链

Gazebo diff drive 提供：

```text
odom -> base_footprint
```

正式运行补齐：

```text
base_footprint -> base_link
base_link -> base_scan
```

最终 TF：

```text
odom
  -> base_footprint
      -> base_link
          -> base_scan
```

固定变换与模型几何保持一致：

```text
base_footprint -> base_link
z = 0.010

base_link -> base_scan
x = -0.064
z = 0.121
```

### 5.6 默认后端

`NavigationNode` 默认：

```text
navigation_motion_backend = nav2
```

Potential Field 仍可显式选择，但不再是正式主线默认后端。

## 7. flake8 并行崩溃处理

ROS 全量测试曾在 `ament_flake8` 内部出现 multiprocessing segmentation fault。

表现为：

```text
flake8/checker.py
multiprocessing.pool
Segmentation fault
```

这不是 SCA/Nav2 功能失败。

最终固定：

```ini
[flake8]
jobs = 1
max-line-length = 99
```

并让：

```text
sca_aifnav_ros/test/test_flake8.py
```

显式使用 `sca_aifnav_ros/setup.cfg`。

注意：

```text
main_with_errors(argv=["--jobs=1"])
```

不可用，因为 `ament_flake8` 自己的 argparse 不接受该参数。
